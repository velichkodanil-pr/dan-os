# DAN.OS — проєкт і план MVP (v1.1)

**Дата:** 12 серпня 2026 · **Статус:** затверджено Данилом · Повна версія з діаграмою: `AI Companion\DAN.OS — проєкт і план MVP v1.1.docx` (OneDrive)

Персональна AI-операційна система: секретар · компаньйон · радник · тренер · товариш · колега.
Формула: **одна особистість → багато ролей → одна керована пам'ять → багато каналів → жодної неконтрольованої автономії.**

## 1. Ключові рішення

| Параметр | Рішення |
|---|---|
| Платформа v1 | Telegram-бот → Mini App (раунд 4) → Android (пізніше, той самий API) |
| Стек | Python (aiogram 3 + FastAPI) на Railway; один сервіс з логічними модулями |
| LLM | Haiku 4.5 (рутина) + Sonnet 5 (складне); provider-neutral інтерфейси |
| Пам'ять | Postgres + pgvector; статуси raw → indexed → candidate → confirmed |
| Дії | Політика L0–L5 у детермінованому коді; зовнішнє — превʼю + підтвердження |
| Домени | personal / travelon / tech — ізольовані |
| Канали | Telegram, Gmail, Calendar, Drive; Travelon read-only (Р4); Zoom/Android пізніше |
| Вартість | ≈ $15–40/міс |

## 2. Принципи

Ядро, а не бот (адаптери без бізнес-логіки) · керована пам'ять з провенансом · джерело правди:
жива система > підтверджена пам'ять > розмова > знання моделі; конфлікти показуються, не
перезаписуються · контрольовані дії (політика = код) · проактивність P0–P3 з бюджетом сповіщень ·
coverage map (бот сам просить дані, ніколи «про всяк випадок») · недовіра до зовнішнього контенту
(prompt injection) · приватність (allowlist, «забудь/експортуй/звідки знаєш»).

## 3. Ролі

Секретар (календар, задачі, дайджест пошти, чернетки) · Компаньйон (брифи, чек-іни, контекст життя) ·
Радник (факти/припущення/рекомендація) · Тренер (цілі, звички, ревю) · Товариш (розмови, гумор) ·
Колега (тексти, таблиці, документи, боти TravelON). Внутрішні механізми: Архіваріус (Memory Service)
і Контролер ризику (Policy Engine, може заблокувати дію).

## 4. Архітектура

Telegram (aiogram 3, webhook) → Оркестратор (FastAPI) → LLM-шар (Haiku/Sonnet, кеш) →
Пам'ять (Postgres+pgvector: профіль, епізодична, база знань, задачі) →
Політика дій (код, L0–L5) → Журнал дій (append-only) → Планувальник (APScheduler) →
Інгестори (Gmail/Calendar/Drive/Whisper). Хостинг: Railway (EU), деплой = push у main.

## 5. Пам'ять

Життєвий цикл факту: **raw** (immutable, dedupe) → **indexed** (пошук, не факт) →
**candidate** (пропозиція ✅/❌) → **confirmed**; + superseded / conflicted.
Кожен факт: зміст, джерело+посилання, дата отримання, дата актуальності, довіра, чутливість,
домен, статус, що замінило. Конфлікти: «дві версії, яка правильна?» — supersede з історією.
Coverage map: пропозиція джерела лише при повторюваних питаннях / ручних завантаженнях /
застарілості / конфліктах; формат: користь + права + ризик + Підключити/Відкласти/Не пропонувати.
Гігієна: «забудь», експорт, TTL сирих логів 30–60 днів, тижневий бекап.

## 6. Проактивність

P0 негайно (навіть у тихі години) · P1 сьогодні · P2 у дайджест · P3 без сповіщення.
Ритуали: бриф 07:30 · нагадування · вечірній чек-ін 21:30 (+ підтвердження кандидатів пам'яті) ·
тижневе ревю нд 19:00 (+ coverage map) · місячний огляд. Тихі години 23:00–07:30.

## 7. Дії L0–L5

L0 читання — авто · L1 внутрішні записи — авто з undo · L2 задача/нагадування — команда або
one-tap · L3 зовнішні зворотні (подія календаря, чернетка) — превʼю + підтвердження ·
L4 комунікація назовні — повне превʼю + повторне підтвердження · L5 гроші/підпис/трейдинг/
безповоротне видалення — заборонено. Ідемпотентність усіх записів; журнал дій без тіл повідомлень
і секретів; жодного SQL/shell/URL у LLM.

## 8. Раунди розробки

- **Р0 Фундамент (1 день):** repo, Railway+Postgres, скелет webhook, статус-файли.
  Гейт: бот відповідає, конвеєр працює.
- **Р1 Наскрізний зріз (~тиждень):** текст/голос → raw event (dedupe) → екстракція → превʼю
  ✅✏️❌ → задача → «Сьогодні» → нагадування → аудит. Тести: replay, подвійний approve,
  заборонена дія, чужий користувач. Гейт: працює з телефона, тести зелені.
- **Р2 Секретар (~тиждень):** Calendar+Gmail read, ранковий бриф, вечірній чек-ін, профіль,
  персона. Гейт: бриф щоранку з реальними даними.
- **Р3 Знання (2–3 тижні):** pgvector RAG (файли, пересилання, Drive), дайджест Gmail,
  чернетки (L3), конфлікти, coverage map v1. Гейт: відповіді з джерелом; ≥1 корисна пропозиція.
- **Р4 Розширення:** Mini App (Сьогодні/Підтвердження/Пам'ять), Travelon read-only пульс,
  тренер/OKR; далі Zoom, Android, ширші L3–L4.

Процес: один раунд за раз, стоп-гейти, STATUS/NEXT/DECISIONS у репо.

## 9. Взято з паралельної специфікації DAN.OS v0.1

Взято: назва і формула; статуси пам'яті + провенанс; ієрархія джерел правди; домени; L0–L5 і
політика в коді; ідемпотентність + append-only аудит; coverage map; P0–P3 + бюджет; vertical
slice як Р1; provider-neutral інтерфейси; anti-injection правила; структура системного промпту;
раунди з гейтами (полегшені).
Відкладено: Mini App (Р4), Web Admin, Redis/S3/Vault/OTel, Travelon gateway (Р4), GitHub,
WhatsApp/Instagram, Health, crypto-observer, Android.
Не взято на старті: мікросервісний монорепо, повний R0–R7 CI-церемоніал, обов'язковий Docker.
